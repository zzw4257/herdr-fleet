## Decisions

- **One panel, two tabs, one element at every width.** It stands as a column in the native navigation shell beside the route (≥1024 px) and fixed over the route below that, so a breakpoint change never reloads a frame inside it. State (open, tab, address, width) is per device, in localStorage as a convenience.
- **Screen costs no read.** The Pane page already holds its Chat window; one hook call publishes the window's newest picture under the Pane's scope key. A picture tapped in Chat is pinned until "follow the newest".
- **Browser frames only the editor's proxy of a loopback address.** Most sites refuse framing, and the editor is the only origin the page policy admits as a frame. The frame keeps its own origin (the editor's sign-in cookies must ride its subresources) and the sandbox withholds top navigation. `allow-scripts allow-same-origin` trips `react/iframe-missing-sandbox`; the owner approved suppressing it at that one attribute, recorded as the fork's second lint exception in AGENTS.md › Linting. A page proxied this way shares the editor's origin, so isolating dev servers from the editor itself needs per-port subdomains — a follow-up.
- **Media bytes come from the picture read's checks.** Files internals are exported and the fork's reader runs them with its own type list (bytes only) and a 64 MiB bound; `files/image?as=media` keeps the route, gate and crew forwarding upstream's. The bytes become this page's own object URLs.
- **PDF is drawn by PDF.js, not framed — measured.** Headless Chrome and Edge draw a `blob:` PDF in an unsandboxed frame and refuse it in any sandboxed one (`sandbox=""`, `allow-scripts`, `allow-same-origin`, both), the lint gate requires a sandbox on every frame, and a phone browser draws no framed PDF at all. The owner approved `pdfjs-dist` (pinned 6.4.299, lazy chunk): pages render onto canvases when near the screen and release their bitmaps when far, WebAssembly is off and the bytes are handed over in memory, so the page policy needs nothing new — verified rendering CJK and standard-font PDFs under Fleet's exact policy. Its worker ships as `.mjs`, so Collie's static type table gains `.mjs`.
- **Scripted HTML is an opaque-origin document.** The Gateway reads the file through Collie's own Files read and answers it with a policy starting `sandbox allow-scripts` (no `allow-same-origin`), `connect-src` absent under `default-src 'none'`, scripts inline or `https:`. Measured: scripts run, `document.cookie` throws, a same-origin fetch is refused. Sibling assets do not load — a known ceiling.
- **The page policy is widened at the Gateway, narrowly.** `frame-src 'self' blob: <editor origin>` and `media-src 'self' blob:` from the page's own fallback; `script-src`, `connect-src`, `object-src` untouched; sandboxed policies untouched.
